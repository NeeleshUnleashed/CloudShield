## 2. Identified Refinements & Corrective Action Plan

Based on the audit, the following safe refinements will bring CloudShield to 100% excellence:

1. **Test Database Isolation (Phase 5 & 6)**:
   - Configure tests to use a dedicated SQLite test database (`data/test_cloudshield.db` or in-memory) instead of the user's demo database (`data/cloudshield.db`). This ensures running `pytest` never wipes or alters live demonstration records.
2. **Formal AWS Service Adapters (`app/adapters/`) (Phase 5)**:
   - Establish clean, modular adapter interfaces for `NotificationAdapter` (Mock SNS vs Live Boto3 SNS) and `StorageAdapter` (Local File vs S3) with `AWS_MODE` switching.
3. **Documentation Alignment (Phase 5 & 8)**:
   - Create `docs/ARCHITECTURE_SPEC.md` directly in `docs/` (consolidating from `deployment/aws/ARCHITECTURE_SPEC.md`).
   - Create `docs/AWS_DEPLOYMENT_PLAN.md` covering pre-deployment steps for EC2, RDS, S3, SNS, CloudWatch, and IAM roles without performing live deployments.
